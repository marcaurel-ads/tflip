# A lean C client API (proposal)

Status: design proposal, nothing implemented. See [DESIGN.md](DESIGN.md) for
why the ACE API is expensive remotely.

`ace32.dll`/`ace64.dll` stay what they are: the drop-in for existing
Advantage applications. This document proposes a second client library,
`libtflip`, for new code and ports: a small C ABI over the same engine API
(`tflip-protocol`'s `Api`), set-based and batched, that any language with a
C FFI can bind and that hands results to data tools without copying.

## Goals and non-goals

Goals:

- **Few calls.** A few dozen functions, against the about 465 exports of
  the ACE API and its `…90`/`…100`/`…101` generations.
- **Batched.** A remote scan of N rows costs about N / batch size round
  trips, not N or more.
- **Plain C ABI.** `extern "C"`, the platform's default calling convention,
  no ordinals, no stdcall decoration, one header generated by `cbindgen`.
  Built for Windows, Linux and macOS, 64-bit; 32-bit Windows where cheap.
- **Interoperable results.** Rows come as Apache Arrow record batches
  through the Arrow C Data Interface, so pyarrow, pandas, polars, DuckDB, R
  and Rust's `arrow` crate read them without binding code.
- **Same engine, same server.** Local mode runs the engine in the process,
  remote mode talks to `tflipd`, exactly as `tflip-ace` does. A table
  written through one library reads the same through the other.
- **Versioned from the start**, so that it can grow without new
  generations of every function.

Non-goals:

- Compatibility with ACE's signatures, constants, error codes or quirks.
- Code pages in the API. Text is UTF-8; the engine converts to and from
  the table's character set.
- Relations (`AdsSetRelation`) and the per-handle settings of ACE
  (`AdsShowDeleted`, `AdsSetExact`, ...) as global state. Where they are
  needed they become arguments of the call that uses them.

## Where it sits

```text
application ─┬─ ace64.dll  (tflip-ace: ACE's API and quirks)  ─┐
             └─ libtflip   (tflip-c: this API)                 ─┴─ tflip-protocol::Api
                                                                     ├─ engine session (local)
                                                                     └─ Client ── tflipd (remote)
```

A new crate, `crates/tflip-c`, builds `libtflip.so`, `libtflip.dylib` and
`tflip.dll`. Like `tflip-ace` it keeps no engine state of its own; unlike it,
it has no compatibility rules to follow, so most calls map onto one `Api`
call. The batch calls need one addition to the protocol (see
"Protocol additions").

## Conventions

| Topic | Rule |
| --- | --- |
| Names | Everything starts with `tflip_` (functions) or `TFLIP_` (constants, enums). |
| Objects | Opaque, typed pointers: `tflip_conn`, `tflip_table`, `tflip_stmt`, `tflip_cursor`, `tflip_txn`. A wrong kind is a compile error, not a run-time 5018. Each has its own `tflip_*_close`, which accepts NULL. |
| Text | UTF-8, as a pointer and a byte length (`const char *s, size_t len`); `len == (size_t)-1` means NUL-terminated. Text the library returns is NUL-terminated UTF-8 it owns. |
| Results | Every function returns `tflip_status` (0 is success). Values come back through out-parameters. |
| Errors | An optional last parameter `tflip_error **err`. When it is non-NULL and the call fails, it receives an error object with a code, a message and, where it applies, the field or SQL position; free it with `tflip_error_free`. Nothing is kept per thread or per connection: there is no "last error". |
| Memory | What the library allocates, the library frees, through the matching `_free`/`_release`. Arrow batches follow the Arrow C Data Interface's `release` callback. No caller-sized buffers, no "too small, call again". |
| Threads | Objects of one connection may be used from any thread, one call at a time per connection (the library serialises). Different connections are independent. |
| Versioning | `tflip_api_version()` returns the library's ABI version; structs passed in start with a `uint32_t size` field, so new members can be added at the end. Functions are only added, never changed; a changed function gets a new name. |

## Objects

| Object | What it is |
| --- | --- |
| `tflip_conn` | A connection: a local folder or dictionary, or a `tflipd` server. |
| `tflip_table` | An open table, for writes, locks and its structure. Reading goes through cursors. |
| `tflip_cursor` | A stream of rows: a table scan, an index range, or a SQL result. Read in batches. |
| `tflip_stmt` | A prepared SQL statement with parameters. |
| `tflip_txn` | A transaction on a connection. |
| `tflip_error` | A failed call's details. |

## The calls

The header below is the whole first version, with comments shortened.

```c
#include <stddef.h>
#include <stdint.h>

typedef int32_t tflip_status;           /* 0 = TFLIP_OK */
typedef struct tflip_error  tflip_error;
typedef struct tflip_conn   tflip_conn;
typedef struct tflip_table  tflip_table;
typedef struct tflip_cursor tflip_cursor;
typedef struct tflip_stmt   tflip_stmt;
typedef struct tflip_txn    tflip_txn;
struct ArrowSchema;                     /* Arrow C Data Interface */
struct ArrowArray;

/* Library */
uint32_t     tflip_api_version(void);
const char  *tflip_status_name(tflip_status status);

/* Errors */
tflip_status tflip_error_code(const tflip_error *err);      /* tflip's own codes */
const char  *tflip_error_message(const tflip_error *err);
void         tflip_error_free(tflip_error *err);

/* Connections */
typedef struct {
    uint32_t    size;                   /* sizeof(tflip_connect_options) */
    const char *location;               /* folder, dictionary, or tflip://host:port/path */
    const char *user;                   /* NULL for none */
    const char *password;               /* NULL for none */
    const char *dictionary_password;    /* for AES dictionaries; NULL for none */
    uint32_t    flags;                  /* TFLIP_CONNECT_* */
} tflip_connect_options;

tflip_status tflip_connect(const tflip_connect_options *opt, tflip_conn **out, tflip_error **err);
void         tflip_conn_close(tflip_conn *conn);

/* Tables: structure, writes, locks */
tflip_status tflip_table_open(tflip_conn *conn, const char *name, size_t len,
                              uint32_t flags, tflip_table **out, tflip_error **err);
tflip_status tflip_table_schema(tflip_table *table, struct ArrowSchema *out, tflip_error **err);
void         tflip_table_close(tflip_table *table);

/* Reading: every read is a cursor */
typedef struct {
    uint32_t    size;
    const char *order;                  /* index order (tag) name; NULL = natural order */
    const void *lower; size_t lower_len;/* key range on the order, inclusive; NULL = open */
    const void *upper; size_t upper_len;
    const char *filter;                 /* expression in the engine's language; NULL = none */
    const char *const *columns;         /* NULL-terminated; NULL = all */
    uint32_t    flags;                  /* TFLIP_SCAN_DESCENDING, TFLIP_SCAN_DELETED, ... */
} tflip_scan_options;

tflip_status tflip_scan(tflip_table *table, const tflip_scan_options *opt,
                        tflip_cursor **out, tflip_error **err);
tflip_status tflip_query(tflip_conn *conn, const char *sql, size_t len,
                         tflip_cursor **out, tflip_error **err);
tflip_status tflip_cursor_schema(tflip_cursor *cur, struct ArrowSchema *out, tflip_error **err);
/* Up to max_rows rows as one Arrow record batch; *rows = 0 at the end. */
tflip_status tflip_fetch(tflip_cursor *cur, uint32_t max_rows,
                         struct ArrowArray *out, uint32_t *rows, tflip_error **err);
void         tflip_cursor_close(tflip_cursor *cur);

/* Prepared statements */
tflip_status tflip_prepare(tflip_conn *conn, const char *sql, size_t len,
                           tflip_stmt **out, tflip_error **err);
/* Parameters as one Arrow record batch: one column per parameter, one row per execution. */
tflip_status tflip_stmt_bind(tflip_stmt *stmt, struct ArrowSchema *schema,
                             struct ArrowArray *rows, tflip_error **err);
tflip_status tflip_stmt_execute(tflip_stmt *stmt, tflip_cursor **out /* NULL if none */,
                                uint64_t *affected, tflip_error **err);
void         tflip_stmt_close(tflip_stmt *stmt);

/* Writing rows */
tflip_status tflip_insert(tflip_table *table, struct ArrowSchema *schema,
                          struct ArrowArray *rows, uint64_t *first_record, tflip_error **err);
/* Updates and deletes address records by record number (a cursor's
   TFLIP_COL_RECNO column) or by the table's primary key. */
tflip_status tflip_update(tflip_table *table, struct ArrowSchema *schema,
                          struct ArrowArray *rows, uint32_t flags, tflip_error **err);
tflip_status tflip_delete(tflip_table *table, const uint32_t *records, size_t count,
                          tflip_error **err);

/* Transactions and locks */
tflip_status tflip_begin(tflip_conn *conn, tflip_txn **out, tflip_error **err);
tflip_status tflip_commit(tflip_txn *txn, tflip_error **err);   /* frees txn */
tflip_status tflip_rollback(tflip_txn *txn, tflip_error **err); /* frees txn */
tflip_status tflip_lock(tflip_table *table, const uint32_t *records, size_t count,
                        tflip_error **err);   /* count == 0: the whole table */
tflip_status tflip_unlock(tflip_table *table, const uint32_t *records, size_t count,
                          tflip_error **err);
```

That is 30 functions. Indexes, dictionary objects, backup and the
management calls are left to SQL (`CREATE INDEX`, the system procedures)
until there is a reason for calls of their own.

## Types

Field types map to Arrow types; the schema's field metadata keeps the
original type name (`tflip.type`), width and decimals, so a round trip can
write the same field back.

| tflip field type | Arrow type |
| --- | --- |
| Logical | `bool` |
| ShortInt, Integer, LongInt, AutoInc, RowVersion | `int16`, `int32`, `int64`, `int32`, `int64` |
| Double, CurDouble | `float64` |
| Numeric | `decimal128(width, decimals)` |
| Money | `decimal128(19, 4)` |
| Date, CompactDate | `date32` |
| Time | `time32(ms)` |
| TimeStamp, ModTime | `timestamp(ms)` |
| Character, CiCharacter, VarChar, LegacyVarChar, Memo, NChar, NVarChar, NMemo | `utf8` (`large_utf8` for memos) |
| Raw, Binary, Image, VarBinary | `binary` (`large_binary` for memo-stored) |
| Guid | `fixed_size_binary(16)` |

NULL is Arrow's validity bitmap. Whether an empty value of a table without
NULL support reads as NULL or as the empty value is a scan flag
(`TFLIP_SCAN_EMPTY_AS_NULL`), not a global setting.

A cursor can add two virtual columns on request: `TFLIP_COL_RECNO` (the
record number, `uint32`) and `TFLIP_COL_DELETED` (`bool`, with
`TFLIP_SCAN_DELETED`).

## Consistency of batches

A batch is read at one moment: each `tflip_fetch` returns rows as they were
when the server read that batch. Rows of later batches can reflect changes
made in between; a cursor is not a snapshot of the whole scan. An
application that needs a consistent view of the whole scan reads inside a
transaction, or uses a static SQL cursor (`tflip_query` of a `SELECT` whose
result is static).

Nothing is cached across calls on the client: there is no current record to
go stale, and a new `tflip_scan` sees the table as it is. This is the
difference from ACE's model that makes the API lean: no edit buffer, no
current record, no refresh.

## Mapping onto the engine API

| This API | `Api` calls today | Notes |
| --- | --- | --- |
| `tflip_connect` | `connect_path` | `tflip://` locations go through `Client` to `tflipd` |
| `tflip_table_open`, `_schema`, `_close` | `open_table`, `table_info`, `close_table` | |
| `tflip_scan` + `tflip_fetch` | `open_index`/`seek`/`skip`/`read_fields` per row | needs `fetch_rows` (below) to be batched |
| `tflip_query` | `create_statement`, `execute_direct` | the cursor is read with `fetch_rows` |
| `tflip_prepare`, `_bind`, `_execute` | `prepare`, `set_param`, `execute` | one `execute` per parameter row at first |
| `tflip_insert`, `_update`, `_delete` | `append_record`, `set_field`, `write_record`, `goto_record`, `delete_record` | needs `write_rows` (below) to be batched |
| `tflip_begin`, `_commit`, `_rollback` | `begin_transaction`, `commit_transaction`, `rollback_transaction` | |
| `tflip_lock`, `_unlock` | `lock_record`, `unlock_record`, `lock_table`, `unlock_table` | |

## Protocol additions

Two new `Api` calls, with a new protocol version:

- **`fetch_rows(cursor, max_rows, columns) -> RowBatch`**: the next rows of a
  scan or SQL cursor, the given columns of each, memo values included,
  positioned by the server. A scan's position, range and filter live on the
  server side of the cursor, so the client keeps nothing but the handle.
- **`write_rows(table, op, rows) -> WriteResult`**: insert, update or delete
  many rows in one request, each row applied as `tflip-ace`'s sequence of
  calls would apply it (constraints, triggers, AutoInc, RowVersion), stopping
  at the first error and reporting which row failed.

`RowBatch` is columnar on the wire (one array per column with a validity
bitmap), so `tflip-c` can hand it to Arrow with little conversion.

`fetch_rows` also gives `tflip-ace` its missing read-ahead: `AdsCacheRecords`
can fill a client-side block from it (see [DESIGN.md](DESIGN.md) and the
read-ahead item in [TODO.md](TODO.md)).

## Phases

1. **Read-only** (**M**): `tflip_connect`, `tflip_table_open`/`_schema`,
   `tflip_scan`, `tflip_query`, `tflip_fetch`, errors, versioning; the
   protocol's `fetch_rows`; a Python example through pyarrow's C Data
   Interface import. Measure a remote scan against ACE's `AdsSkip` loop.
2. **Writes** (**M**): `tflip_insert`, `_update`, `_delete`, prepared
   statements with bound batches, transactions, locks; the protocol's
   `write_rows`.
3. **Bindings** (**S** each): a thin Python package, and others on demand.
   Rust code uses the engine crates directly and needs none of this.

## Open questions

- **Range keys.** `lower`/`upper` as raw key bytes are exact but need the
  caller to know the index's key format. A typed form (an Arrow scalar per
  key segment, converted by the engine as `Key::Text` is today) is friendlier;
  maybe both.
- **Filter language.** The engine's expression language (as ACE filters
  use it) or a SQL `WHERE` fragment. The first is what the engine already
  evaluates on scans; the second is what new users know.
- **Updates by position.** Record numbers are cheap and exact but not stable
  across a pack; a primary key needs one. Both are offered above; whether
  updating by record number should require a lock is open.
- **Async.** A non-blocking `tflip_fetch` (a poll or a callback) would let a
  client overlap the network with its own work. Left out of the first version.
- **Arrow dependency.** The C Data Interface is two structs and needs no
  Arrow library; `tflip-c` can produce them with the `arrow` crate's FFI
  module or on its own. Callers that do not use Arrow need a small helper to
  read a batch (`tflip_batch_*` accessors) or a row-oriented fetch as well.
